# 1. Información general

## Nombre del proyecto
Amerike MBA 2026

## Objetivo principal
Desarrollar una aplicación multiplataforma en Flutter que permita a usuarios de distintos perfiles simular inversiones de proyectos en distintas categorías, desde distintos dispositivos conectados a una red local, mientras una computadora principal muestra en tiempo real un dashboard con los resultados y el ranking de inversiones


## Problema que resuelve
Actualmente no existe una herramienta local y en tiempo real que permita registrar y visualizar de forma organizada las inversiones simuladas que realizan distintos usuarios sobre varios proyectos desde diferentes dispositivos. Esto dificulta el control del saldo por usuario, el seguimiento de las inversiones por proyecto y la proyección inmediata de resultados y rankings en una computadora principal

## Resultado esperado
Se espera contar con una aplicación multiplataforma en Flutter que permita a los participantes iniciar sesión o registrarse como invitados, consultar su saldo disponible, invertir en distintos proyectos y ver reflejadas sus acciones en tiempo real en una computadora principal con dashboard y ranking. El sistema deberá permitir además la administración de usuarios, perfiles, proyectos e inversiones, manteniendo un proceso ordenado, claro y funcional para una simulación de inversión sin dinero real.

## Público o usuarios principales
Los usuarios principales del sistema serán alumnos, docentes, administrativos, invitados e inversionistas, quienes utilizarán la aplicación desde smartphones, tabletas o computadoras para simular inversiones en distintos proyectos. También existirá un usuario administrador encargado de crear, consultar, actualizar y eliminar usuarios, perfiles, proyectos e inversiones. Adicionalmente, organizadores, evaluadores o público podrán visualizar los resultados en tiempo real desde la computadora principal o pantalla de proyección.

# 5. Reglas de negocio

- El sistema manejará únicamente dinero ficticio para fines de simulación; no se permitirá ningún pago real ni integración financiera
- Cada usuario tendrá un monto inicial de inversión determinado por su perfil
- Los perfiles iniciales serán: alumno, docente, administrativo, invitado, inversionista y admin; el sistema deberá permitir hasta 10 perfiles distintos
- Los montos iniciales por perfil serán: alumno $1,000,000 MXN; docente $4,000,000 MXN; administrativo $6,000,000 MXN; invitado $2,000,000 MXN; inversionista $10,000,000 MXN.
- Un usuario no podrá invertir más dinero del saldo disponible en su cuenta.
- Cada inversión deberá registrarse con usuario, monto, fecha y hora.
- El saldo del usuario deberá actualizarse inmediatamente después de registrar una inversión.
- El total invertido de cada proyecto deberá actualizarse en tiempo real en la app y en el dashboard principal.
- El ranking del dashboard deberá ordenarse automáticamente de mayor a menor según el total invertido por proyecto, salvo que el admin defina otro criterio.
- El sistema deberá soportar hasta 100 usuarios en esta versión.
- El sistema deberá soportar hasta 10 temas o categorías de proyectos.
- Cada proyecto deberá pertenecer al menos a un tema o categoría.
- Solo el administrador podrá crear, editar o eliminar usuarios, perfiles, proyectos, temas e inversiones.
- El registro como invitado permitirá acceso sin validación de correo ni confirmación externa.
- El username deberá ser único para evitar duplicidad de usuarios; si ya existe, el sistema deberá impedir el registro.
- El correo electrónico podrá registrarse sin validación externa, pero podrá requerirse que no se repita si tú así lo defines.
- El temporizador de inversión será global y configurable por el administrador.
- Mientras el temporizador esté activo, los usuarios podrán registrar inversiones; al llegar a cero, el sistema deberá bloquear nuevas inversiones.
- Si el administrador modifica el temporizador, el nuevo tiempo deberá reflejarse en todos los dispositivos conectados.
- Todos los dispositivos participantes deberán conectarse a la computadora principal por red local.
- La computadora principal actuará como punto central para sincronizar la información en tiempo real dentro de la red local

# 7. Flujo del usuario

## Pantalla 1: Inicio de sesión
Debe mostrar:
- Logo o nombre de la aplicación.
- Campo para username.
- Campo para password.
- Botón “Iniciar sesión”.
- Botón “Invitado”.
- Mensaje de error en caso de datos incorrectos.
- Opción para mostrar u ocultar la contraseña (opcional).

Acciones:
- Escribir su username.
- Escribir su password.
- Presionar el botón “Iniciar sesión”.
- Presionar el botón “Invitado” si no tiene credenciales.

Validaciones:
- El campo username es obligatorio para iniciar sesión.
- El campo password es obligatorio para iniciar sesión.
- El sistema debe validar que las credenciales coincidan con un usuario registrado.
- El sistema no debe permitir acceso si el usuario está inactivo.

Comportamiento del sistema:
- Si el username y password son correctos, el sistema debe permitir el acceso a la pantalla principal.
- Si el username o password son incorrectos, el sistema debe mostrar un mensaje de error y permanecer en la misma pantalla.
- Si el usuario selecciona “Invitado”, el sistema debe enviarlo a la pantalla de registro de invitado.
- Si algún campo obligatorio está vacío, el sistema debe indicar que faltan datos antes de continuar.

Mensajes sugeridos
- “Ingresa tu username.”
- “Ingresa tu password.”
- “Usuario o contraseña incorrectos.”
- “Tu usuario está inactivo.”
- “Continúa como invitado si no cuentas con acceso.”

Resultado esperado
- El usuario autenticado entra a la pantalla principal.
- El usuario sin credenciales puede ir al flujo de invitado.
- El usuario con datos incorrectos recibe retroalimentación clara sin salir de la pantalla.


## Pantalla 2: Registro como invitado
Objetivo de la pantalla
Permitir que una persona sin credenciales previas pueda registrarse rápidamente como invitado para entrar al sistema y participar en la simulación.

Debe mostrar
- Título “Registro como invitado”.
- Campo para nombre completo.
- Campo para correo electrónico.
- Campo para username.
- Campo para password.
- Botón “Continuar”.
- Botón “Regresar” o “Volver al inicio de sesión”.
- Mensajes de error o validación en caso necesario.

Acciones del usuario
- Escribir su nombre completo.
- Escribir su correo electrónico.
- Escribir un username.
- Escribir una password.
- Presionar el botón “Continuar” para registrarse.
- Presionar “Regresar” si desea volver a la pantalla de inicio de sesión.

Comportamiento del sistema
- El sistema debe registrar al usuario con perfil “invitado”.
- El sistema no debe solicitar confirmación por correo ni validación externa.
- Si todos los campos requeridos están completos, el sistema debe permitir el acceso a la pantalla principal.
- Si falta algún dato obligatorio, el sistema debe mostrar un mensaje y no continuar.
- Si el username ya existe, el sistema debe informar el problema y pedir uno diferente.
- El sistema debe asignar automáticamente al invitado el monto de inversión correspondiente a su perfil.

Validaciones
- El nombre es obligatorio.
- El correo es obligatorio.
- El username es obligatorio y debe ser único.
- La password es obligatoria.
- El correo debe tener formato válido si decides validar formato.
- No es necesario verificar que el correo exista realmente.

Mensajes sugeridos
- “Completa todos los campos.”
- “El username ya está en uso.”
- “Ingresa un correo válido.”
- “Registro completado correctamente.”

Resultado esperado
- El usuario queda registrado como invitado.
- El sistema le asigna el saldo correspondiente a ese perfil.
- El usuario entra automáticamente a la pantalla principal para comenzar a invertir.

# 8. Dashboard de la computadora principal

## Objetivo del dashboard
Mostrar en tiempo real el comportamiento general de la simulación de inversión, permitiendo visualizar el total invertido por proyecto, el ranking de proyectos, el estado de la ronda y la evolución de las inversiones desde una computadora principal conectada a todos los dispositivos participantes.

## Quién lo verá
- Público asistente al evento.
- Jurado o evaluadores.
- Organizadores del evento.
- Usuario administrador.
- Moderadores o responsables de la dinámica.
[Ejemplo: público, jurado, organizadores, admin]

## Componentes visuales
- Gráfica de barras de: total invertido por proyecto.
- Ranking en tiempo real de: proyectos ordenados de mayor a menor según el monto total invertido.
- Totales generales de:
  - monto total invertido en toda la simulación,
  - número total de inversiones registradas,
  - número total de usuarios participantes,
  - proyecto con mayor inversión acumulada.
- Filtros por tema: Sí, para visualizar solo los proyectos pertenecientes a un tema o categoría específica.
- Filtros por perfil: Sí, para visualizar inversiones realizadas por tipo de usuario, por ejemplo alumnos, docentes, administrativos, invitados o inversionistas.
- Actualización automática: Sí.

## Orden del ranking
El ranking deberá ordenarse automáticamente de mayor a menor según el monto total invertido acumulado por cada proyecto en tiempo real.

En caso de empate entre dos o más proyectos, el sistema podrá desempatar usando alguno de los siguientes criterios:
- el proyecto que alcanzó primero ese monto,
- el mayor número de inversiones registradas,
- o mantener el mismo orden anterior hasta que exista una diferencia.

El orden del ranking deberá actualizarse automáticamente cada vez que se registre una nueva inversión.

## Qué métricas debe mostrar
- Monto total invertido acumulado en toda la simulación.
- Monto total invertido por cada proyecto.
- Número total de inversiones registradas.
- Número total de usuarios participantes.
- Saldo total restante entre todos los usuarios (opcional).
- Proyecto con mayor inversión acumulada.
- Tema o categoría con mayor inversión acumulada (opcional).
- Promedio de inversión por usuario (opcional).
- Promedio de inversión por proyecto (opcional).
- Tiempo restante de la ronda de inversión.
- Estado actual de la ronda: abierta, pausada o cerrada.
- Posición actual de cada proyecto dentro del ranking.
- Variación de posición en el ranking respecto a la actualización anterior (opcional).
- Última hora de actualización del dashboard.

- Las acciones principales del usuario, como iniciar sesión, cambiar de pantalla o registrar una inversión, deben reflejarse en un tiempo corto y adecuado para la dinámica del evento.
- La información crítica, como saldo disponible, total invertido por proyecto, temporizador y ranking, debe actualizarse en tiempo real o con un retraso mínimo perceptible.
- El dashboard principal debe reflejar los cambios realizados desde otros dispositivos en un tiempo aproximado de hasta 1 segundo, siempre que la red local esté funcionando correctamente.
- El sistema deberá soportar hasta 100 usuarios en esta versión sin afectar de forma crítica la experiencia general.

## Seguridad
- El sistema utilizará autenticación básica mediante username y password.
- Al tratarse de un simulador local sin dinero real, no se requiere en esta versión autenticación avanzada ni integración con servicios externos de verificación.
- Solo los usuarios con perfil admin podrán acceder al módulo de administración.
- El sistema deberá impedir el acceso si las credenciales son incorrectas.
- El sistema deberá restringir las acciones administrativas a usuarios autorizados.
- De ser posible, las contraseñas deberán almacenarse de forma protegida y no en texto plano.

## Uso sin internet
- Sí.
- El sistema deberá funcionar sin conexión a internet externa.
- Los dispositivos deberán conectarse entre sí mediante red local para compartir información en tiempo real.
- Si no existe conexión a internet pero sí conexión a la red local, la aplicación deberá seguir operando normalmente.

## Compatibilidad
- La aplicación deberá desarrollarse en Flutter.
- Deberá funcionar en smartphones, tabletas y computadoras compatibles con la versión elegida del proyecto.
- Deberá adaptarse a distintos tamaños de pantalla, manteniendo una interfaz usable y legible.
- Deberá ser compatible al menos con Android, Windows y, si se define posteriormente, con iOS, macOS o versión web.
- La interfaz deberá mantener coherencia visual tanto en orientación vertical como en pantallas más amplias.

## Límite de datos
- Hasta 100 usuarios registrados o conectados en la versión inicial.
- Hasta 10 perfiles de usuario.
- Hasta 10 temas o categorías.
- La cantidad de proyectos por tema podrá definirse posteriormente, pero deberá mantenerse dentro de un volumen adecuado para una simulación fluida.
- El sistema deberá manejar únicamente información relacionada con usuarios, perfiles, temas, proyectos, inversiones, temporizador y resultados de la simulación.

# 12. Casos especiales

- ¿Qué pasa si se cae la conexión local?
  El sistema deberá mostrar un aviso de conexión perdida y evitar nuevas operaciones que dependan de sincronización en tiempo real hasta recuperar la conexión. La información ya visible podrá mantenerse en pantalla como última versión conocida. Cuando la conexión regrese, el sistema deberá reconectarse y actualizar los datos automáticamente.

- ¿Qué pasa si dos usuarios invierten al mismo tiempo?
  El sistema deberá procesar ambas inversiones en el orden en que sean recibidas por la computadora principal o servidor local. Ambas operaciones deberán registrarse correctamente, actualizar el saldo de cada usuario y reflejarse en el dashboard en tiempo real sin perder datos.

- ¿Qué pasa si un usuario intenta invertir más de lo que tiene?
  El sistema deberá rechazar la operación y mostrar un mensaje indicando que el monto excede el saldo disponible. No deberá registrarse la inversión ni modificarse el saldo del usuario.

- ¿Qué pasa si el admin borra un proyecto con inversiones?
  El sistema deberá solicitar confirmación antes de eliminarlo. Si el proyecto tiene inversiones registradas, se recomienda no permitir su eliminación física y en su lugar marcarlo como inactivo o deshabilitado para conservar el historial y evitar inconsistencias.

- ¿Qué pasa si un usuario cierra la app y vuelve a entrar?
  Si el usuario ya está registrado, podrá volver a iniciar sesión con sus credenciales y recuperar su información actualizada, incluyendo saldo disponible e historial correspondiente. Si la ronda sigue activa, podrá continuar usando el sistema con normalidad; si la ronda ya terminó, solo podrá consultar la información permitida.

# 14. Criterios de aceptación

## El sistema se considerará correcto si:
- El usuario puede iniciar sesión con username y password válidos y acceder a la pantalla principal.
- Un usuario sin cuenta puede registrarse como invitado y entrar al sistema sin validación externa.
- A cada usuario se le asigna correctamente el saldo inicial según su perfil.
- El usuario puede ver su saldo disponible actualizado en todo momento.
- El usuario puede navegar entre temas, proyectos y detalle del proyecto sin errores.
- El usuario puede registrar una inversión en un proyecto activo.
- El sistema impide registrar una inversión mayor al saldo disponible del usuario.
- El saldo del usuario disminuye correctamente después de cada inversión aceptada.
- El total invertido del proyecto se actualiza correctamente después de cada inversión.
- El dashboard principal refleja los cambios de inversión en tiempo real o con retraso mínimo perceptible.
- El ranking de proyectos se actualiza automáticamente de mayor a menor según el monto invertido.
- El temporizador de la ronda se muestra correctamente y puede ser configurado por el admin.
- Al llegar el temporizador a cero, el sistema bloquea nuevas inversiones.
- El admin puede crear, consultar, editar y eliminar o desactivar usuarios, perfiles, temas, proyectos e inversiones según las reglas definidas.
- El sistema funciona en red local sin depender de internet externa.
- El sistema soporta la operación esperada de hasta 100 usuarios dentro del alcance definido para la primera versión.
